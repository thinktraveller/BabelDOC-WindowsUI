## 四、未验证项（需要用户配合时再补）

1. **无 Python 的干净 Windows 10/11 x64 机器**上运行便携目录与安装包：需要虚拟机或独立机器。
2. ~~**真实 LLM API 翻译**~~：**已于 2026-09-20 验证**。用界面中保存的 `deepseek` 配置（`https://api.deepseek.com/v1`、模型 `deepseek-flash`）对一份自建英文样例（1 页、约 856 字符、5 段）执行真实翻译：引擎发出 2 次 `chat/completions` 请求并全部返回 200，6 段翻译 6 成功 0 回退，31.1 秒产出单语与双语 PDF 及术语 CSV，退出码 0；产物正文确为中文译文。**仍未验证**的是术语表在真实译文中的替换效果（本次未绑定术语版本）。
3. **交互式界面点击**：拖拽多文件、非法页码高亮、关闭窗口三选项——逻辑均有接口/单元测试覆盖；界面骨架已有 2 项组件测试（标题、标签页、设置入口、未配置 API 时的引导），但没有做真实拖拽与点击的端到端自动化（本机浏览器自动化通道不可用）。

   另记录两个已修复的真实启动缺陷：

   - 冻结版双击启动（无控制台，`sys.stdout` 为 `None`）时 uvicorn 日志初始化抛异常、进程在建窗口之前退出。修复提交 `016fa6d`（标准流兜底 + 关闭 uvicorn 自带日志配置 + 启动标记 + 崩溃日志同时写应用日志目录），新增 7 项回归测试。
   - 窗口打开后显示「未响应」，且会话令牌注入失败导致界面所有请求被 403 拒绝。根因是桌面桥把 pywebview `Window` 对象挂在公开实例属性上，pywebview 递归导出 JS 对象时无限展开。修复提交 `80a2346`（桥状态移到模块级、前端请求前等待令牌），新增 5 项回归测试；修复后释出版本窗口连续 101 秒保持响应、令牌第 1 次尝试注入成功、无 403 告警。
   - 选中 PDF 后点「导入选中文件」报 `HTTP 422`。根因是 Ant Design 传给 `beforeUpload` 的条目没有 `originFileObj` 字段，导入按钮过滤后得到空数组，上传表单里没有文件字段。修复提交 `dc7282d`（补齐 `originFileObj`、新增 `resolvePendingFiles()`、上传前等待令牌、422 文案可读化），新增 2 项组件测试；修复后组件测试断言上传表单含 1 个 File 字段，冻结版首页引用的脚本已确认包含该修复。
4. **离线（断网）启动 + 完整资源包**：需要构造断网环境。
5. 安装包本体：`installer.iss` 已提供，但本机没有安装 Inno Setup，**未实际编译**。
